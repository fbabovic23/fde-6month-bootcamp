# FDE Curriculum Addendum: the 26-Week Plan

This file sits on top of `fde_curriculum.pdf`. The PDF still holds the day-by-day reading and tasks. This addendum sets the calendar, says which PDF days are CORE and which are STRETCH, and replaces a few days. **Where the two disagree, this file wins.**

Upload it to the FDE 6-months Mentor project next to the PDF.

## Why it exists
- The PDF plans 60–90 minutes of reading plus 90–120 minutes of build for every day. The daily slot is 75–90 minutes. So each week is cut to its CORE days, and reading is done only when the build needs it.
- Two catch-up weeks are added, which makes 26 calendar weeks: November 23, 2026 to May 23, 2027.
- Three content changes: an early AWS deploy in Week 4, a retrieval (RAG) build in Week 11, and AWS as the only cloud in Week 22.

## How a week works
- **Week numbers are curriculum weeks 1–24**, the same numbers the PDF uses. The two catch-up weeks have names, not numbers.
- **CORE day:** do the hands-on deliverable in one 75–90 minute session. Start with the build. Read only what unblocks it.
- **STRETCH day:** skip it if you are behind. If you are on time, do it. Log a skipped day as `skipped (stretch)`.
- **Sunday:** only the Sunday deliverable from the PDF (a short note or a 3 to 5 minute recording). No other build work.
- **Order:** always work on the next open CORE day, in order. The calendar shows where you should be. If you are behind, you stay on your own next day and the calendar runs ahead of you until a catch-up week absorbs the gap.
- **More than a week behind after a catch-up week:** do not extend the plan. Tell the Mentor how many days you are behind and cut scope from the current phase together.

## Catch-up weeks
- **Catch-up Week A:** January 18–24, after Week 8.
- **Catch-up Week B:** March 22–28, after Week 16.

What to do in one:
1. Finish every open CORE day, oldest first.
2. Then do the STRETCH days you skipped, most useful first.
3. Do the readiness tasks listed for that week in `PROGRESS.md`.
4. If nothing is open, rest. Do not start the next week early.

No new curriculum, no scheduled comm gym drill. You may repeat one drill you did badly.

**Moving one:** if you know a week will be lost (travel, holidays, a work deadline), you may take a catch-up week early, once each. Every later date then moves by a week, and that catch-up week is gone from its default place.

## Replaced days

### Week 4, Friday: first AWS deploy
Deploy the Incident Triage Service to AWS so that it answers on a public HTTPS URL.
- Push the image to Amazon ECR and run it with Amazon ECS Express Mode, which creates the Fargate service, the load balancer and the URL for you.
- For this first deploy the database may be the Postgres container you already have, or SQLite. A managed database comes in Week 22.
- Acceptance check: `curl https://<your-url>/docs` returns the OpenAPI page, and one create-and-read request works.
- **Delete the service when the check has passed.** The load balancer and the Fargate task cost money for every hour they run.
- Saturday's `v1.0.0` tag and README then include one line on how it was deployed.

Why: the 26 AWS scenarios are practiced on paper every Wednesday from Week 1, and the PDF does not touch a cloud until Week 22. One early deploy makes the Wednesday drills concrete.

### Week 11, Wednesday to Friday: retrieval (RAG) build
Reading for these days: Chip Huyen, *AI Engineering*, Chapter 6.
- **Wednesday:** collect about 30 policy or tariff documents (public or synthetic). Chunk them, embed them, and store them in Postgres with `pgvector`. Write a retrieval function that returns the top results with their source IDs.
- **Thursday:** build an answer endpoint that cites its sources. When nothing relevant is retrieved, it must say so and hand off instead of guessing.
- **Friday:** write a 20-question eval set (question, expected source, expected answer). Report retrieval hit rate and answer accuracy. Then change the chunk size once and record what happens to both numbers.

Why: question answering over a customer's own documents is the request in workbook cases WB6 and WB11 and in architecture scenario Q24, and the PDF has no retrieval build. It replaces three days of multi-agent orchestration, which stay available as STRETCH.

### Week 22: AWS only
Where the PDF says "Google Cloud Run or AWS ECS", use AWS: ECS on Fargate, Secrets Manager, RDS for PostgreSQL, IAM roles, and GitHub Actions with OIDC. Run `terraform destroy` at the end of every session and check the billing page once this week.

### Week 24: warning
Each day of the final capstone is written as a full day of a field engagement. It will not fit a 90-minute slot. Choose one:
- plan about 3 hours a day for this one week, or
- on the Sunday of Week 23, lock a thinner scope: one workflow, one MCP tool set, the eval suite and the cloud deploy you already have.

Decide on the Sunday of Week 23 and write the choice in `PROGRESS.md`.
